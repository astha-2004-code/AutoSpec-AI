# Production Deployment Guide — Neon + Render + Vercel

AutoSpec AI 2.0 is designed for free/low-cost cloud production hosting with zero paid LLM lock-in:

- **Database & Vector Index**: Neon PostgreSQL with `pgvector`
- **Backend API**: Render Web Service (`Dockerfile` + `render.yaml`)
- **Frontend UI**: Vercel (`frontend/vercel.json`)

---

## 1. Provision Neon PostgreSQL + `pgvector`

1. Create a free Neon project in AWS US-West (Oregon) or matching your Render region.
2. Open the **Neon SQL Editor** and run:
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ```
3. Copy both connection strings from the Neon dashboard:
   - **Pooled connection string** (`-pooler` hostname) -> set as `DATABASE_URL`
   - **Direct / Unpooled connection string** -> set as `DATABASE_URL_UNPOOLED`
4. Run initial Alembic migrations against Neon from your workstation or CI:
   ```bash
   DATABASE_URL_UNPOOLED="postgresql+psycopg2://USER:PASS@HOST/neondb?sslmode=require" alembic upgrade head
   ```

---

## 2. Deploy Backend to Render

1. Push the branch/repository to GitHub.
2. In Render, select **New -> Blueprint** and point to `render.yaml`, or create a **Web Service** using `Dockerfile`.
3. Configure the required secret environment variables in Render:
   - `DATABASE_URL` (Neon pooled URL, with `?sslmode=require`)
   - `DATABASE_URL_UNPOOLED` (Neon direct URL, with `?sslmode=require`)
   - `AUTOSPEC_ALLOWED_ORIGINS` = `["https://YOUR-APP.vercel.app"]` (no trailing slash)
   - `AUTOSPEC_SECRET_KEY` (auto-generated by Render Blueprint)
   - `AUTOSPEC_EMBEDDING_PROVIDER` = `onnx` *(default local 384-dim quantized ONNX, <200 MB RAM)* or `gemini` *(zero local model RAM, uses `AUTOSPEC_LLM_API_KEY`)*
   - `AUTOSPEC_EMBEDDING_MODEL` = `Xenova/all-MiniLM-L6-v2` *(or `gemini-embedding-001` if using `gemini` embeddings)*
   - `AUTOSPEC_LLM_PROVIDER` = `gemini` *(or `none` for deterministic offline extraction)*
   - `AUTOSPEC_LLM_MODEL` = `gemini-2.5-flash`
   - `AUTOSPEC_LLM_API_KEY` = your Google AI Studio Gemini API key
4. Confirm health check passes at:
   `https://YOUR-RENDER-API.onrender.com/api/v1/health`
   Verify `"database_backend": "postgresql"` and `"pgvector_enabled": true`.

---

## 3. Deploy Frontend to Vercel

1. In Vercel, click **Add New -> Project** and import your GitHub repo.
2. Set **Root Directory** to `frontend`.
3. Framework Preset: **Vite** (`npm run build`, output directory `dist`).
4. Add Environment Variable:
   - `VITE_API_BASE_URL` = `https://YOUR-RENDER-API.onrender.com`
5. Deploy! `frontend/vercel.json` handles React Router SPA fallbacks and security headers automatically.
6. Copy the live `https://YOUR-APP.vercel.app` domain back into Render's `AUTOSPEC_ALLOWED_ORIGINS` and redeploy/restart Render if needed.

---

## 4. Cold-Start & Persistence Notes

- Render free-tier web instances spin down after 15 minutes of inactivity and wake in ~30–50 seconds; the React frontend shows a non-blocking status indicator in the header and retries transient 502/503 responses automatically.
- Because Render container disks are ephemeral, `WorkspaceService` persists `pdf_data` (`BYTEA`), `document_pages`, `document_chunks`, `chunk_embeddings` (`vector(384)`), and `specifications` in Neon PostgreSQL so uploaded manuals, citations, and PDF previews recover seamlessly across container restarts.
